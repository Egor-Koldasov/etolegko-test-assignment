# Измерение скорости скачивания

Консольный скрипт на TypeScript: принимает HTTP(S)-адрес, выполняет **10 последовательных GET-запросов**, полностью читает каждый ответ и выводит среднее время запроса, общий объём данных и скорость скачивания.

## Запуск

Нужен **Node.js 22.18 или новее**. TypeScript запускается напрямую встроенным механизмом удаления типов — сборка и установка зависимостей для запуска не нужны.

```sh
node speedtest.ts
```

Без аргумента используется `https://speed.cloudflare.com/__down?bytes=10000000` — ресурс для проверки скорости Cloudflare, возвращающий 10 000 000 байт. Полный запуск скачает **100 MB**. Можно передать другой HTTP(S)-адрес, например прямую ссылку на большой файл.

```sh
node speedtest.ts --timeout 60
node speedtest.ts 'https://speed.cloudflare.com/__down?bytes=1000000'
node speedtest.ts --help
```

`--timeout` задаёт максимальное время одного запроса целиком, включая чтение тела, в секундах. По умолчанию — 30 секунд. Допустимы дробные значения от 0.001 до 2147483.647.

Пример формата результата (числа времени и скорости зависят от соединения):

```text
Completed requests: 10
Average request time: 1.000 s
Downloaded: 100000000 bytes (100.000 MB)
Download speed: 10.000 MB/s
```

## Как считается результат

- Время каждого запроса измеряется монотонным `performance.now()` непосредственно перед `fetch` и до полного чтения тела ответа.
- Среднее время = сумма времени 10 запросов / 10.
- Общий объём = сумма фактически прочитанных байтов тел ответов; заголовку `Content-Length` для подсчёта не доверяем.
- Скорость = общий объём / сумма времени запросов / 1 000 000.
- **MB = 1 000 000 байт; MB/s — мегабайты в секунду**, не мегабиты и не MiB/s.

Ответ читается порциями и не сохраняется на диск. Следующий запрос начинается после полного чтения предыдущего. Используются стандартные перенаправления и переиспользование соединений `fetch`; перенаправления входят во время запроса и могут добавлять HTTP-обмены. Дополнительных прогревочных запросов и повторов нет.

Запрашивается `Accept-Encoding: identity`. Если сервер всё же возвращает сжатое тело, выполнение завершается ошибкой: `fetch` автоматически распаковывает такие ответы, что исказило бы подсчёт скачанных байтов. Считаются только байты тела, без HTTP-заголовков и служебных данных TLS/TCP.

При HTTP-ошибке, сетевой ошибке, обрыве ответа или тайм-ауте скрипт останавливается, пишет номер запроса и причину в stderr и возвращает код 1. Итог успешного замера для неполных 10 запросов не печатается. Код успешного завершения — 0.

Это эффективная скорость скачивания с конкретного сервера, а не максимальная пропускная способность подключения: результат зависит от маршрута, VPN/прокси, сервера, установления соединения и размера ресурса. Для слишком маленького файла задержки особенно заметны. Cloudflare — пример, доступность ресурса зависит от сети.

## Разработка и проверки

```sh
npm ci
npm run check
```

Отдельно:

```sh
npm run typecheck
npm test
npm start -- 'https://speed.cloudflare.com/__down?bytes=10000000'
```

Зависимости нужны только для разработки: `typescript` и `@types/node`. Node удаляет типы, но не проверяет их; эту задачу выполняет `tsc --noEmit`. Включены строгая проверка и `erasableSyntaxOnly`; используются ESM и явные расширения `.ts`.

Тесты используют `node:test` и локальный HTTP-сервер, без внешней сети. Проверяются последовательность 10 запросов, чтение отложенных порций, подсчёт байтов, формулы, HTTP-ошибки, обрывы, тайм-аут тела ответа, сжатие и поведение CLI.
